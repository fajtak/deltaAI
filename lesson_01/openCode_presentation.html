Tokenizace – Jak AI čte text

Model nepracuje se slovy, ale s tokeny

tokenizer_interactive.py
# Zadejte text a sledujte, jak se rozdělí na tokeny:

BPE (Byte Pair Encoding): Často používaná slova = 1 token, neznámé = rozdělené na podtokeny. Zkuste napsat český vs anglický text!
Příklady tokenizace:
"Ahoj" → 1 token
"Programování" → 4 tokeny
"AI" → 1 token
"Hello" → 1 token
"Programming" → 3 tokeny
"🤖" → 1-2 tokeny
// 05

Tokenizace – podrobnosti

Jak BPE funguje

  • Začni bajty (0-255)
  • Najdi nejčastější pár bajtů
  • Slouč ho v nový token
  • Opakuj, dokud nedosáhneš limitu slovníku
# Český text bývá méně efektivní:
"Ahoj světe" → [6 tokenů]
"Hello world" → [2 tokeny]

1 token ≈ 4 znaky v angličtině
1 token ≈ 2-3 znaky v češtině

Proč je to důležité?

💡 Kontextové okno
Maximální počet tokenů, které model "vidí". GPT-4: 128K ≈ 96K slov ≈ kniha.
💰 Ceník
API se účtuje za tokeny. Více tokenů = vyšší náklady.
🌍 Jazyková nerovnost
Angličtina má nejlepší pokrytí. Čeština vyžaduje více tokenů pro stejný obsah.

Trénování – Jak se učí

Cross-Entropy Loss

L = -Σ p(x) · log(q(x))

Model přiřadí pravděpodobnost každému tokenu ve slovníku. Trénink minimalizuje rozdíl mezi predikcí a skutečným dalším tokenem.

Gradient Descent

# Animace gradientního sestupu
learning_rate: 0.5
f(x): 0.12(x-3)² + 1
minimum: x = 3

Learning rate ovlivňuje, jak velké kroky model dělá. Příliš velký → přeskakuje minimum. Příliš malý → učí se pomalu.

Generování textu – Sampling

Jak model vybírá slovo z mnoha možných?

sampling_demo.py
# Top-K & Top-P sampling
temperature: 1.0 (posuvník: 0.0 - 2.0)
top_k: 5 (posuvník: 1 - 10)

Původní: textu 40%
Po teplotě 0.5: textu 52% (zesíleno)
Po teplotě 1.5: textu 28% (zeslabeno)
🎯 Greedy Decoding
Vždy vybere nejpravděpodobnější token. Deterministické, ale generuje repetitivní a nudný text.
🎲 Random Sampling
Vybere token náhodně podle distribuce. Kreativní, ale může generovat nesmysly.
⚖️ Top-K + Temperature
Kombinace: ořež na K nejlepších + uprav teplotu. Standardní přístup pro ChatGPT.
// 11

Teplota a Top-P

🌡️ Teplota (Temperature)
Mění "ostrost" distribuce pravděpodobností:
Temperature 1.0
p_i = exp(z_i / T) / Σ exp(z_j / T)
🎯 Top-P (Nucleus Sampling)
Ořeže distribuci na nejmenší množinu tokenů s kumulativní pravd. ≥ P:
Top-P 0.9
💡 Praxe: OpenAI doporučuje měnit buď teplotu, nebo Top-P, ne obojí najednou.

😵‍💫 Halucinace – Když AI vymýšlí

Model generuje text, který zní přesvědčivě, ale není pravdivý

❌ Typická halucinace
"Albert Einstein získal Nobelovu cenu za teorii relativity v roce 1921."

✓ Opravdu: Cenu dostal za fotoelektrický jev.

❌ Vymyšlená kniha
"Kniha 'Propasti minulosti' od Jana Nováka."

✓ Tato kniha ani autor neexistují.

Proč k halucinacím dochází?

  • Model optimalizuje na pravděpodobnost, ne na pravdu
  • Nemá přístup k realitě
  • Trénovací data mohou obsahovat chyby
  • Vysoká teplota zvyšuje riziko
🛡️ Obrana
  • RAG (Retrieval-Augmented Generation)
  • Ověřování faktů
  • Nízká teplota
  • Citace zdrojů

RLHF – Učení od lidí

Reinforcement Learning from Human Feedback

📝 Sběr dat od lidí
→
🏆 Trénování reward modelu
→
🎮 RL optimalizace (PPO)
→
✅ Bezpečnější model
Fáze 1: Supervised Fine-Tuning
Lidé píší příklady ideálních odpovědí. Model se učí základní formát a styl odpovídání.
Fáze 2: Reward Model
Lidé hodnotí více odpovědí od nejhorší po nejlepší. Model se učí předpovídat, která odpověď se člověku líbí.
Bezpečnostní trénink: RLHF je důvod, proč moderní LLM odmítají nebezpečné požadavky.
📊 Kolik práce to stojí?
OpenAI najal tisíce annotátorů z Keni a Evropy. Každý hodnotitel stráví stovky hodin posuzováním odpovědí. Náklady: desítky milionů dolarů.
🆕 DPO – nová cesta
Direct Preference Optimization – obechází reward model. Přímo optimalizuje z preferencí lidí. Jednodušší, levnější, stále efektivní.
🛡️ Constitutional AI
Anthropic používá sadu principů ("ústavu"), podle kterých AI hodnotí vlastní odpovědi. Méně závislosti na lidech.

Praktické tipy pro práci s LLM

1. Prompt Engineering
  • Buďte konkrétní
  • Ukážte příklad (few-shot)
  • Rozložte úkol na kroky
  • Požádejte o formát
2. Ověřujte odpovědi
  • Nezaměňujte jistotu za přesnost
  • Ověřujte fakta a čísla
  • Používejte nástroje pro data
  • Queryujte model kriticky
3. Vybírejte správný model
  • Malé modely pro jednoduché úkoly
  • Větší pro komplexní reasoning
  • Specializované pro domény
  • Local vs. API – trade-off
